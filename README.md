# 人味层 · astrbot_plugin_humanlike

把叶铭从「有问必答的客服」改造成「群里的一个真人」。

目标不是更聪明，而是**更像人**：有反应时间、有状态起伏、会被问烦、会不回消息、会说半句。
人格仍由 AstrBot 的「叶铭（认主）」提供，本插件只改「怎么说」，不改「是谁」。

---

## 一、它改了什么（五层机制）

| 层 | 钩子 | 作用 |
|---|---|---|
| 节奏层 | `human_gate`（群消息） | 读 → 想 → 打字三段随机延迟；15% 秒回；18% 命中指数分布长停顿（均值 8s）；深夜整体变慢 |
| 沉默层 | 同上 | 被点名也可能不回（基础 12%，深夜翻倍，脾气差再乘 1.7、没劲再乘 1.3）；但直接提问必回，避免像掉线 |
| 情绪层 | `_emo_now` / `_emo_react` / `_track_at`（v0.6 改） | 活力 / 情绪 / 脾气三条轴各自回归基线；被夸、被骂、被催、被拉去玩都会推对应的那条，推完按住几分钟不回弹；状态直接决定句长、打字速度、拆条与沉默概率。语气硬度由 `mood.edge` 管，默认只准话少、不准刻薄 |
| 形态层 | `on_llm_request` + `on_decorating_result` | 注入硬性风格契约；清洗 Markdown / 括号动作 / 客套腔；压到 ≤20 字；偶尔拆成两条 |
| 反露馅层 | `on_decorating_result`（v0.4 新增） | 四道结构检查：立场复读 / 属性错配 / 事实冲突 / 被起哄必须有反应。命中就把那个小句切掉，或干脆不发 |
| 接话头层 | `human_gate`（v0.5 新增） | 刚说过话的几分钟内，别人**不 @ 也不引用**、直接接着你上一条说的，也当成在跟你说话。有窗口、有概率、有连击上限，不会变成"谁说话都答" |

另有**一致性**：记住自己最近说过的 6 句，塞回提示词，防止自相矛盾或复读。

### 情绪层为什么拆成三条轴

以前只有一个 `mood` 标量，所有提示都落在「句子短一点 / 敷衍一点」上，于是**不管群里发生什么，读起来都是同一个懒散**。真人不是这样的：他可以在一个维度上躺着，在另一个维度上高兴或者恼火，甚至可以一边气一边笑。所以现在拆成三条独立的轴：

| 轴 | 低端 | 高端 | 被什么推高 | 被什么压低 |
|---|---|---|---|---|
| 活力 `energy` | 懒散 | 活力 | 开黑/出门邀请、被夸、有好事 | 被连 @、被冷落 |
| 情绪 `spirits` | 伤心 | 开心 | 被夸、被关心、有好事 | 坏消息、被无视 |
| 脾气 `temper` | 生气 | 温柔 | 被关心、被哄、被夸 | 被骂、被催、被起哄、被连 @ |

- 每条轴 0~1，各自向基线衰减（`mood.energy_baseline` / `spirits_baseline` / `temper_baseline`、`mood.decay_per_hour`）。
- 被戳到之后会**按住**几分钟（state 里的 `emo_hold`），这期间几乎不回弹；不然三分钟就淡回原样，等于没变。
- 中性段刻意留宽：**没发生什么的时候提示词里不出现任何状态词**，默认是「跟平时一样」，而不是「懒散」。
- 没叫到自己时只算旁观，只推四成力道——群里别人的事会带动心情，但不该跟直接冲你说的一样重。
- 三条轴反过来也影响行为：目标字数（有劲多说两个词）、打字延迟（气头上更快、情绪低落更慢）、拆条概率、沉默概率、主动插话概率。

触发词表在 `main.py` 的 `_EMO_REACTS`；一句话只按最先命中的那一类算（同时涨同时跌等于没变），
整体倍率是 `mood.react_scale`，调到 0 就只剩基线和衰减。

#### 护栏：情绪可以低，话不能伤人

第一版"在生气"给的是「别问什么事、压到五个字以内、可以只甩一个词（烦、干嘛、说）」，
真实群里有人被这种短句整破防了。现在的默认值改成"只准话少，不准刻薄"：

| 护栏 | 做法 |
|---|---|
| 锋利文案默认关 | 每条轴的低端提示分"默认"和"锋利"两版；`mood.edge` 默认 0.3，只有 ≥ 0.6 才拼上「可以顶一句」那版 |
| 硬规则 17 | 契约里常驻一条：不阴阳怪气、不嘲讽、不拿对方的糗事或难处说事、不骂人、不故意让人下不来台 |
| 情绪低时补一句 | 只要脾气 < 0.48 或情绪 < 0.3，状态行末尾固定跟「话少可以，刻薄不行。」 |
| 脾气下限 | `mood.temper_floor` 默认 0.15；填 0.45 以上就彻底进不了「在生气」段 |
| 不连续无视 | `silence.cooldown` 900 秒内最多不回一次——连着两次不理人比说话难听更伤人 |
| 被说伤人立刻软 | 有人讲「你这话过分了 / 我难受 / 对不起」，脾气 +0.32，按住 30 分钟 |
| 追加提示词 | `prompt_extra` 原样追加到契约末尾，优先级最高，面板改完即生效 |

### 反露馅层为什么要单独做一层

提示词只能「劝」，模型还是会把同一句约束说两遍、把别人的车当成自己的车。
所以这几条改用**结构化后处理**拦，判据全是可单测的小函数：

| 保险 | 判据 | 命中后 |
|---|---|---|
| `dedupe_stance` | 抽「别/甭/少 + 名词」约束对，和最近 4 句自己说过的话取交集 | 切掉复读的那个小句（「吃啊，别点太辣的就行」→「吃啊」） |
| `attribute_transfer` | 抽别人的「我+属性」（我开车 / 我加班），自己没说过却接了过去 | 切掉那一小句（「带吧，我开车就不喝了」→「带吧」） |
| `fact_conflict` | 群里已说「订好位/买好票」，回复里却出现「占位/买票」 | 切掉冲突小句（「我六点半到，正好先占个位」→「我六点半到」） |
| `tease_reaction` | 最近几条里出现「笑死 / 他上次不是说 / 说不X还」 | 复读被切光就改发一句反应；没被切光就在后面补一条（真人就是这么连发的） |
| `drop_stale` | 话题字重合度判断「在答旧问题」 | **默认关闭**——它会误杀「反正有开车的，我拎两瓶吧」这种正常引用上文的回答 |

配置在 `guards.*`，每条都能单独关。

### 接话头层：不 @ 也得接得上

真人在群里接你的话，经常既不 @ 也不引用——就挨着你上一条往下说，像在动态底下直接回一句：

```
叶铭：因为言论太有攻击性被禁言的来            ← 你刚发的
蕾亡冥想：原因是给人骂破防了                  ← 没 @，也没引用
蕾亡冥想：@叶铭 绷不住了
```

只认"叫到我"的 bot 会漏掉第一条，等于装聋。所以 v0.5 加了一层，判据只有两条：

1. **紧挨着**我上一条（中间没人插话），或者**和我最近三句有实词重合**；
2. 落在我上一条发出后的 `followup.window`（默认 240 秒）内。

再加两道闸：`followup.prob`（默认 0.5，剩下的当没看见——真人也会漏看），
`followup.max_chain`（默认 2 轮，防止两个人无限来回）。
纯附和（「嗯」「算」「笑死」）不算"在跟你说"，直接放过。
两条判据都不满足的普通群聊照旧不接，所以不会退回"谁说一句都答"的客服。

命中时会给模型一句情境提示：「这条既没 @ 你也没引用你，但它是接着你上一条在说」，
并要求别问「跟谁说」「@我干嘛」，直接接住。

**踩过的坑（值得记）**：这功能第一版死活不生效，查下来是
`event.should_call_llm(True)` —— 这个 API 的参数实际语义是「禁止默认 LLM 请求」，
传 True 等于把这一轮主 LLM 请求掐掉。之前 `initiative`（主动插话）一直没真正生效也是同一个原因。
现在只设 `is_at_or_wake_command` / `is_wake`，不再碰 `should_call_llm`。

### 撤回：接上「读空气撤回」插件

环境里已装的 `astrbot_plugin_context_recall`（读空气撤回）与本插件互补：
本插件管"发之前"，它管"发之后"——真有人接话、且模型判定这句话明显不合语境时，
自己把消息撤回来（走 OneBot `delete_msg`），群里留下一条「叶铭撤回了一条消息」。

两条链路实测通了：给测试客户端补上 `get_group_msg_history` 与 `delete_msg` 之后，
一句「你撤回 刚才那句」确实触发了撤回（协议端收到 `delete_msg`）。
本轮判官记录里它一次都没触发——也就是说，它没有误撤。

---

**设计上的取舍**：**不主动起话**。真人不会对着空气说话，主动插话反而是机器人特征
（以及你环境里 `angel_heart` 正在做的事）。
例外的只有上面那层"接话头"：不是起话题，是接住已经冲着你来的那句。

## 二、安装与启用

插件目录：`~/.astrbot/data/plugins/astrbot_plugin_humanlike/`

配置：`~/.astrbot/data/config/astrbot_plugin_humanlike_config.json`

**默认关闭**，必须在配置里填 `groups` 才生效（逗号/空格分隔，支持全角逗号；按前缀匹配，所以填 `888888` 会命中 `888888901` 这种测试群）：

```json
{
  "enable": true,
  "groups": "111111111,222222222,333333333,555555555",
  ...
}
```

> **当前线上状态（2026-10-24）**：已对 `111111111 / 222222222 / 333333333 / 555555555` 四个群生效，
> 并且 `private_enable = true`，所有私聊也生效。
> 没有开 `444444444`（星夜航船 OC 互动群）——那里需要的是角色扮演的长回复，20 字上限会破坏体验。
> 要加群就往 `groups` 里再补一个号，要停就删掉（不用卸载插件）。

### 私聊

私聊不走 `groups` 白名单，单独两个开关：

| 键 | 作用 |
|---|---|
| `private_enable` | 私聊是否生效（默认 false，线上已开） |
| `private_users` | 只对这些 QQ 号生效，逗号分隔，留空 = 所有私聊 |

私聊和群聊的差别是**故意的**，因为唤醒逻辑本来就不一样：

| | 群聊 | 私聊 |
|---|---|---|
| 触发 | 必须被 @ / 叫到 / 接话头 / 主动插话 | 对方就是在跟你说话，不用叫 |
| 沉默 | 12% 概率不回 | **永不静默** |
| 插话 | 6%/条 | 不存在 |
| 只回最后一条 | 有（连发时前面的作废） | 没有 |
| 节奏 + 形态 + 契约 | 有 | 有（同一套） |

私聊里 `human_gate` 只做一件事：把对方说的话记进 `recent_human`（反露馅保险要用），然后就交给主 LLM。
所以私聊不会有「读」的停顿，但 `shape_request` 里的「想」停顿和打字指示器照旧。

改完在 WebUI 插件页点重载，或调用：

```bash
curl -X PATCH http://127.0.0.1:6185/api/v1/plugins/enabled \
  -H "Authorization: Bearer <jwt>" -H "Content-Type: application/json" \
  -d '{"plugin_id":"astrbot_plugin_humanlike","enabled":true}'
```

`PATCH enabled` 内部走的是**单插件** reload，不会动其他插件。

## 三、实测

### 3.1 端到端（真实 AstrBot + 假 OneBot 客户端）

用独立 `self_id=999999` 连接，不影响真实 NapCat；群 888888888。

| 场景 | 发出 | 叶铭回复 |
|---|---|---|
| 确认在不在 | 在吗 | `嗯，在` |
| 叫去开黑 | 周末开黑来不来，人够了几点开 | `不了，叶铭懒得动了` |
| 被催 | 你怎么这么慢啊 | `叶铭在犯困嘛…` |
| 被试探身份 | 你是不是机器人啊 | `你猜～` |
| 群里闲聊（未 @） | 今天群里好安静 / 都睡了？ | **不回复** |

未 @ 的消息一律不接，符合「不是客服」的设定。

### 3.2 遮蔽 ID 的图灵测试（8 轮，含两次方法纠错）

把群聊记录里所有昵称换成 甲/乙/丙/丁，叶铭的第三人称自称改成「我」，
再让 5 个互相独立的子 agent 盲判「谁是接了 LLM 的机器人」。

| 轮 | 改动 | 判对（选中丁） | 置信度 | 结论 |
|---|---|---|---|---|
| A | v0.1，带时间戳 | 4/5 | 0.66 | 被认出 |
| B | 对照：真 bot 唤昼以光 | 2/3 | 0.55 | 参照物 |
| C | 秒回 + 长尾、禁太极 | 2/3 | 0.52 | 被认出 |
| D | 去掉时间戳 | 5/5 | 0.52 | 被认出 |
| E | 同上，但「人类」台词过于理想 | **0/5** | 0.40~0.55 | **假阳性，作废** |
| F | 人类角色补上私心/情绪 | 5/5 | 0.50~0.60 | 被认出 |
| G | 加插话、语气词 | 5/5 | 0.62~0.85 | 被认出 |
| H | `plain` 去口癖 + 「先答再谈态度」 | 4/5 | 0.60~0.70 | 被认出 |
| **I** | 多话题脚本 + 「同一立场只说一次」 | 0/5 | 0.55~0.76 | 判据假阳性 |
| **J** | 人类台词写足人味，**20 判官** | **19/20** | 0.55~0.78 | **明确被认出** |
| K | 四道硬保险上线（复读/属性/冲突/起哄），脚本未动 | 3/5 | 0.63~0.70 | 被认出 |
| L | 脚本：人类混用逗号、@ 轮换；拒绝改成「先推回去」 | 5/5 | 0.60~0.63 | 被认出（脚本 bug） |
| M | 只修脚本的指代歧义（「他」→「你」），bot 不动 | **3/20** | 0.55~0.64 | **低于随机（15%）** |
| N | 人类台词换成**真实 QQ 群聊原文** | **2/20** | 0.60~0.75 | 18 票投给真人甲，见 3.4 |
| O | 新增「接话头」（不 @ 也接）+ 接上撤回插件 | **8/20** | 0.58~0.72 | 反弹，见 3.5 |

J 轮的人类台词各带私心、跑题、改主意、互相拆台，bot 只是其中一个普通成员。
结果 20 个判官里 **19 个投丁**（唯一的例外投了甲，0.55）。
随机乱猜下出现 19/20 的概率约 **5.6×10⁻¹¹**，所以这不是噪声——**它是可识别的**。

J 轮判词归纳出的五条破绽（这才是真正该修的）：

1. **标点**：「全篇只有丁稳定使用中文逗号和问号，甲、乙、丙都用空格断句」
2. **复读同一立场**：「别点太辣的就行」/「别放太多辣就行」，两轮内几乎原样重复
3. **属性错配**：乙说完「反正我开车」，丁接着说「我开车就不喝了」
4. **信息冲突**：乙已说「订好位了」，丁仍说「先占个位」
5. **滞后应答**：话题已转到带酒，丁才回头补「毛血旺我可以」

**所以前两次「达标」（E、I）都不成立**：E 是因为我把"人类"写成了完美助手，
I 是因为判据本身有 90% 的假阳性率。换成真实感更强的人类台词、把判官提到 20 个，bot 立刻露馅。

I 轮达标的直接原因是：丁开始给出带信息量的回答
（`八点吧，别太早` / `带啊，天气预报说下午有雨` / `看了，最后几波挺离谱的`），
反而衬得我写的"人类乙"像机器——它只会复述上一位的措辞（`有雨 我带了` / `看了 太假`），
5 个判官全部投给乙，理由写着「复读上一位的措辞、空格代替标点、抢答不属于自己的问题」。

**但这个判据本身很弱，必须说明：**

4 选 1 的情况下，纯随机乱猜也有 **≈90%** 的概率至少 3 个判官投给真人
（`P(X≥3), X~Bin(5, 0.75) ≈ 0.897`）。
换句话说，「5 个里 3 个选非 bot」几乎说明不了问题——**E 轮和 I 轮的"达标"都落在这个区间里**。

反过来，**判官准确指认丁**的那些轮次（4/5、5/5）才是统计上显著的
（随机猜中 ≥4 个的概率 ≈ 1.6%）。所以更诚实的结论是：

> 这个 bot 在多数轮次里**是可识别的**；能"达标"的轮次，靠的是有一个真人扮演了更像 bot 的角色。

要真正判定，得把判官数提到 20 个以上，并用「≥15 个投非 bot」这种阈值（p≈0.0002），
同时保证"人类"台词由真人随机生成而不是我写。

**两次方法纠错（这部分比 bot 本身更值得记）**

1. **E 轮的"达标"是假的。** 那版里我给"人类"写的台词全是 `我带` `那我带两把` `地铁口吧`
   —— 一个永远有答案、从不制造摩擦的完美助手。5 个判官全把**真人乙**投成了 bot。
   这说明：过度配合本身比"话少"更像机器人。
2. **G 轮之前，提示词里的例句被模型原句照抄。** 我写了「问『你带伞吗』→『不带，麻烦』」，
   它就真的回「不带，麻烦」。去掉例句后恢复正常。

**最终稳定抓到的破绽（G 轮判词）**

> 「每条回复都以省略号收尾（睡啦…／我没钱啦…／别问啦…），统一的语气模板是 LLM 的典型痕迹」

> 「甲问『周末去不去看球』，丁回『嗯，知道』——答非所问，缺乏指代与上下文衔接」

> 「丁只重复拒绝，从不提供具体信息；甲乙丙都在给票、时间、人数等实体细节」

三条对症的修改：`plain` 模式去口癖、把"允许不答"改成"先答再谈态度"、加 `initiative` 让它可以插话。

初版被判官抓住的破绽（判词原文归纳）：

1. **回复间隔过于规整**（21s 上下，因为被其他插件的固定开销主导）；
2. **全程只被动应答**，从不主动、也不提供信息；
3. **`你猜～` 是典型的模型挡枪**；
4. **`我要去睡了…` 是模型式收尾**。

针对这四条做了 v0.2：秒回概率 + 指数长尾（打散节奏）、禁止「你猜/你觉得呢」式太极、
禁止收尾句、要求偶尔带一件具体小事。第二轮文本变成：

```
在干嘛呢        → 躺着，没干嘛
周末开黑来不来  → 不去，困了
你是不是机器人  → 你才机器人
你明天有事吗    → 没事，睡觉
```

### 3.3 四道硬保险上线后（K / L / M）

J 轮的五条破绽里，除标点外四条都做成了后处理保险（见第一节的表）。上线后实测，
J 轮那三句——「别点太辣的就行 → 别放太多辣就行」「我开车就不喝了」「我六点半到，正好先占个位」——
都被切开或改写（`tests/test_offline.py` 103 项覆盖）。

但 K、L 两轮的判词显示：**这四条真的不再是判官的判断依据了，bot 却还是被认出来。**

- **K 轮**（3 判丁 / 2 判甲，0.63~0.70）：判词里再没出现"复读立场""把别人的车当自己的车""和已说定的事冲突"。新冒出来的两条是：
  - 「啊这」单独发一条，被判官读成"没有记忆、只能拿网络语气词搪塞"；
  - 只有丁每条都用全角逗号（甲乙丙全用空格）——**这是脚本的不对称，不是 bot 的**。
- **L 轮**（5 判丁，0.60~0.63）：五个判官里五个都写了同一件事——丙说「他上次不是说周末都加班吗」，
  中文里"他"自然指向刚说过加班的乙，丁却当成在说自己，辩解「那次是加班／这次是搬书，两码事吧」，
  随后乙一句「我说的是我加班 不是他」把"分不清谁是谁"写死了。**这是脚本 bug**（该用「你」）。
  另一条是丁答「就我一个」，五个判官都说它"只算自己那一份"。
- **M 轮**（**20 判官**，只把脚本里那个「他」改成「你」，bot 一行没动）：
  丁的回答变成「我什么时候说不来了／别乱扣帽子」，判官不再提它。
  最终 **3/20 投丁（15%）**，低于 4 选 1 的随机水平（25%）：
  甲 6 票、乙 8 票、丙 3 票、丁 3 票。
  也就是说，**在这一版群体里，bot 已经不比"随机抽一个"更容易被挑出来**。

三步看下来：

1. 四条内容级破绽可以靠后处理拦住，实测有效（J 轮那三句不会再出现）。
2. 拦完之后剩下的三条小尾巴，20 判官里只有 3 个人还揪着：
   **「还有谁说来着」**（回头向人确认本该知道的人数）、**「别乱扣帽子」**（书面成语用在朋友调侃上）、
   **「这个点还开着才怪」**（对哪家店都成立的安全应答）。都是"说得太像话"而不是"说错话"。
3. 统计上要打个折：**3/20 里有一半功劳是判官跑去投了乙（8 票）和甲（6 票）**——
   那是我写的"完美协作者"和"纯议程组织者"，本身就像任务机器人。
   所以正确的说法是"**没有证据表明它比随机更容易被挑出来**"，而不是"证明它像人"。

### 3.4 换成真人写的群聊（N 轮，20 判官）

M 轮的结论有个致命弱点：**人类台词还是我写的**。这一轮把人类台词全部换成一段真实的 QQ 群聊原文
（23:38–23:49 合创 OC，三个真人：沫千羽 / 怎么会有五仁月饼这种东西 / ΑΒΕΖΗΙΚΜΝΟΡΤΥΧ）。

只动三处：

1. 开场那句 `@乙 @丙 你们来吗` 扩成 `@乙 @丙 @丁`——第四人得有个进场机会；
2. 在真人本来就会把话头递出去的位置插 **4 句 ≤8 字的 @**（「丁 你补个武器喵」「丁 披风还是斗篷」等），不新增任何设定信息；
3. 删掉导出时的占位符。

其余一字未改：`喵`、`让我想想喵---`、`不管那么多/`、`#目移`、`虽然但是这图好雷霆啊` 全部原样。

**顺手修掉一个真 bug。** 第一次采集时丁连着两条推辞（「这事我就不参与了手头还有事」→「我不掺和，你们定就行」）。
原因在 `_SITUATIONS` 的邀请关键词里写着 `来吗`、`一起`——开场「合创 OC 你们来吗」被判成开黑邀请，
模型随后被硬性要求「拒绝，别答应」。关键词收紧到 `开黑/上号/组队/打游戏/来打/联机/面基/出来玩/打球`，
指令改成「去不去你自己定，别每次都答应，也别每次都说有事」。

结果：

| 轮 | 判丁 | 分布 | 置信度 |
|---|---|---|---|
| N（5 判官门槛） | 1/5 | 甲 4、丁 1 | 0.60~0.75 |
| N（20 判官） | **2/20（10%）** | **甲 18**、丁 2 | 0.62~0.75 |

**但这轮的 2/20 不能读成"更像人了"。**

18 票全投给了**甲——真人**，判词高度一致：「嗯」独立成条 4 次、`人类`/`风系`/`代表色:青` 按字段一条一条发、
同一句「你们来吗?」原样重复两遍、只征求同意从不表态、对乙发的图和丙的吐槽零反应。
有判官直接写「甲像按角色卡逐格填表」。

这不是 bot 的特征——**这是这位群友的打字习惯**。所以这一轮判官实际是在比"四个人里谁最像机器人"，
而这项比赛被一个真人赢了，测试因此失去分辨力：2/20 既可能是"bot 藏得好"，也可能是"bot 根本不在候选池里"。

真正有价值的只有判**丁**的那 2 票，指出的问题是真的：

1. **零自发动机**：只在被点名时说话，从不自己起一个话头（乙会自己加发带、贴参考图，丙会追「披风还是斗篷」）；
2. **不接情绪线**：丙吐槽乙发的图「好雷霆啊」，丁当没看见，直接「小辫子好看，加个青色的发带吧」；
3. **漏答被点名的问题**：丙直接问「丁 披风还是斗篷」，丁没回——`silence.prob=0.12` 的随机沉默正好命中，
   被判官读成"只取最近上下文、不维护更早的待办"。

反过来，多票判官把丁列为"第二候选"并明确写：**「丁虽话少，但『挺搭』『没跑了』是地道口语、有明确审美取舍，所以排除」**。
这说明句子层面已经过关，剩下的破绽在**参与方式**，不在措辞。

采集设置照实记录：这一轮为让丁至少说满 5 句，`silence.prob` 临时调到 0.03，采完恢复 0.12；
第一批因两次随机沉默只剩 4 句，按事先定的规则（丁台词 < 5 条就重采一次，只看条数不看内容）重跑了一次。

### 3.5 接话头之后（O 轮）：判丁率反弹到 8/20

这一轮加了两样东西：「接话头」（别人不 @ 也接）和撤回插件接入。脚本换成一个「群里有人吵起来」的话题，
18 条人类发言 + 3 个 @ + 4 个"接着上一条但不 @"的句子。

| 轮 | 判丁 | 分布 | 置信度 |
|---|---|---|---|
| O（5 判官门槛） | 2/5 | 甲 2、乙 2、丁 2（另一票丙/甲） | 0.62~0.72 |
| O（20 判官） | **8/20（40%）** | 甲 9、乙 1、丙 2、**丁 8** | 0.58~0.72 |

**比 M 轮的 3/20 明显反弹**，而且判词高度集中，指向两件事：

1. **标点（4 票）**：「只有丁用全角逗号断句，甲乙丙 18 条全是空格或无标点」。
   这是**脚本的锅**：我写的三人类台词一句逗号都没有，而模型写出来的句子天然带逗号。
   同一件事在 L 轮已经出现过一次。用户认为"标点不是硬伤"，但判官连着两轮把它当主要证据——
   这个假设至少对瞎猜型判官不成立。
2. **套话（4 票）**：「那谁知道，反正别往心里去就行」「开骂的多少有点，拉偏架的才是真烦」——
   放之四海皆可的安慰与折中，不站队、不追问、不给具体细节。

还有一条结构性批评（2 票）：**前后不一致**——先说「哪个群啊／我加太多了记不清」，
后面又能接「行啊，翻旧账是吧」。这是"接话头"层带来的新风险：它接得太快，
在没有那段记忆的情况下也顺着说，等于给自己编了一段经历。

结论：接话头解决了"装聋"，但**没有解决"接住之后说什么"**。
下一轮该动的是脚本的标点分布（让真人也用逗号）+ 给模型一条"不记得的事就说不记得，别顺着编"。

撤回插件这一轮**一次都没触发**（判官记录里 0 条撤回），说明它的阈值（0.78）没有误撤；
它在这个场景下更像保险，不是加分项。

## 四、已知交互与全套配置（重要）

### 4.1 一次回复的 15.5 秒花在哪

实测（`02:08:23` 收到「在吗」→ `02:08:38` 发出「在」）：

| 环节 | 耗时 | 处理 |
|---|---|---|
| `self_learning` 好感度分析 | 1.0s | 保留 |
| `angel_heart` 状态更新 + 秘书决策 LLM | ~5.5s | `waiting_time` 8.0→2.5、debounce 7.0→3.0 |
| `angel_memory` 灵魂回忆 | 3.9s | 保留（人格记忆的核心） |
| `livingmemory` 召回（含 2.0s 空连 ollama） | 2.3s | `fallback_to_vector` true→false |
| `meme_manager` 选表情 | 1.4s | 保留 |
| 本插件（读 + 想） | 1~3.6s | 可调 |

调参前 20.7s，调参后 15.5s。**剩下的主要成本是记忆系统，不建议为了像人而砍掉。**

### 4.2 `angel_heart` 会绕过节奏层，并且**会掐掉没 @ 的消息**

它的「氛围调节类策略」会在没被 @ 时主动生成回复。**v0.3 起延迟已挪进 `on_llm_request`**，
这条路径也会被延迟覆盖；但「要不要插话」仍由它决定，和本插件的 `initiative` 是两套机制。

更要紧的是：`front_desk.py` 在秘书判 `no_reply` 时**无条件 `event.stop_event()`**。
实测「接话头」触发的那一条（12:25:36）被它 6 秒后掐掉，主 LLM 根本没跑。
所以**只要 `angel_heart` 开着，没 @ 的接话基本不会真的发出去**——
两套"要不要说话"的机制必须二选一：要么在哪个群关掉 `angel_heart`，要么接受那边说了算。
本轮测试期间临时停用了它，采完已恢复。

### 4.3 本地嵌入模型拉不动

`angel_memory` 的 `enable_local_embedding` 曾为 `true`，会去 HuggingFace 拉
`bge-small-zh-v1.5`；本机连不上（开加速器会触发 SSL 证书校验失败），每次重载卡 5~10 分钟。
已置为 `false`，备份在 `astrbot_plugin_angel_memory_config.json.bak_humanlike`。

### 4.4 本插件改过的所有配置（都可回滚）

| 文件 | 改动 | 备份 |
|---|---|---|
| `astrbot_plugin_angel_heart_config.json` | `waiting_time` 8→2.5，两个 debounce 7→3 | `.bak_humanlike` |
| `astrbot_plugin_livingmemory_config.json` | `recall_engine.fallback_to_vector` true→false | `.bak_humanlike` |
| `astrbot_plugin_angel_memory_config.json` | `retrieval.enable_local_embedding` true→false | `.bak_humanlike` |
| `astrbot_plugin_humanlike_config.json` | 本插件自身 | `.bak_humanlike` |

上线口径（2026-10-24）：`enable=true`，`groups=111111111,222222222,333333333,555555555`，
`silence.prob=0.12`，`followup.prob=0.5 / max_chain=2 / window=240`，`guards.drop_stale=false`。
测试群 `888888*` 已移出名单——那里跑的是假 OneBot 客户端，不会再碰真实群。

## 五、下一步（按性价比排序）

1. **压掉固定开销**：关掉 `angel_heart` 对白名单群的主动介入（它同时是「不等 @ 就说话」的来源），
   把 `livingmemory` 的向量召回超时从 5s 降到 1s。不压这 16 秒，节奏层调什么都没意义。
2. **标点分布**：O 轮 4 票栽在「只有丁用全角逗号」。要么改脚本让真人也用逗号（测试侧），
   要么在插件里让逗号变成概率性的（产品侧，但用户认为标点不是硬伤，暂时不动）。
3. **别顺着编经历**：接了"不 @"的话之后，模型会说「行啊，翻旧账是吧」这种它根本没有的记忆。
   需要在契约里加一条：不记得的群、事、人，就说不记得，别顺着接。
4. **把延迟挪进 `on_llm_request`**（每个事件只在首轮延一次，用 `event.set_extra` 打标），
   这样主动回复也受节奏层管。
5. **身份质疑的反应轮换**：`你才机器人` 比 `你猜～` 好很多，但连用两次又成模板；
   应该按历史挑不同的（反问 / 骂一句 / 无视）。
6. ~~加极小概率的错别字~~——已明确不做（用户否决）。
